# Расписание

Веб-приложение для составления учебного расписания. Сервер проверяет занятость групп, преподавателей и аудиторий, сохраняет переносы и отмены, ведёт историю изменений.

Курсовой проект по бэкенд-разработке. Основная логика находится в Python-сервисе; React-клиент позволяет проверить её через браузер.

[Открыть приложение](https://blaycker.com/mireabackr/) · [Архитектура](docs/ARCHITECTURE.md) · [Тестирование](docs/TESTING.md) · [Развёртывание](deploy/README.md)

## Как попробовать

1. Откройте приложение. Оно создаст личное демо с примером расписания.
2. В разделе «Роль и профиль» выберите диспетчера или администратора и примените роль.
3. Создайте учебный период и черновик, добавьте занятие. Попробуйте назначить другое занятие на то же время для той же аудитории.
4. Опубликуйте расписание, перенесите или отмените занятие и откройте его историю.
5. Переключитесь на студента или преподавателя, чтобы посмотреть опубликованное расписание без возможности редактирования.

Изменения видны только в вашем демо. Сессия хранится в cookie и действует семь дней. Другой браузер или очистка cookies создадут новое пространство. Выбор роли предназначен для демонстрации: администратор не получает доступ к данным других посетителей.

## Возможности

- Недельное расписание с фильтрами по группе, преподавателю и аудитории.
- Справочники групп, преподавателей, аудиторий и дисциплин.
- Учебные периоды, черновики и публикация расписания.
- Проверка пересечений, вместимости аудитории и границ учебного периода.
- Повторяющиеся занятия с предпросмотром серии перед сохранением.
- Перенос и отмена с обязательной причиной и историей «до/после».
- Защита от перезаписи устаревшей версии занятия.
- Адаптивный интерфейс для компьютера и телефона.

| Роль | Опубликованные занятия | Черновики и редактирование | Справочники |
| --- | --- | --- | --- |
| Студент | Просмотр | Нет | Нет |
| Преподаватель | Просмотр | Нет | Нет |
| Диспетчер | Просмотр | Да | Только чтение |
| Администратор | Просмотр | Да | Редактирование |

Группа и преподаватель в профиле задают начальный фильтр, а не ограничивают просмотр внутри личного демо.

## Технологии

| Часть | Используется |
| --- | --- |
| Сервер | Python, FastAPI, Pydantic |
| Данные | PostgreSQL 15, SQLAlchemy, Alembic |
| Ограничение запросов | Redis, атомарный Lua script; Compose использует Redis 7.4 |
| Клиент | React, TypeScript, Vite, CSS |
| Проверки | pytest, HTTPX, Node.js test runner |
| Развёртывание | Docker Compose, Uvicorn; внешний Nginx/HTTPS |

Это модульный монолит: один FastAPI-процесс обслуживает API и React-клиент. PostgreSQL хранит данные; Redis хранит только временные счётчики ограничений запросов. Приложение не разделено на микросервисы.

## Локальный запуск

Основной воспроизводимый способ — Docker Compose. Образ сам собирает клиент; локальные Python и Node для этого способа не нужны.

```powershell
Copy-Item .env.example .env
# В .env задайте APP_ENV=development, PUBLIC_ORIGIN=http://localhost:8187,
# APP_BASE_PATH=/ и собственный POSTGRES_PASSWORD (URL-safe либо URL-encoded).
docker compose up --build -d
docker compose ps
```

Откройте [localhost:8187](http://localhost:8187). Compose запускает PostgreSQL и Redis с healthcheck, выполняет `alembic upgrade head` отдельным одноразовым сервисом `migrate`, затем запускает приложение от пользователя с UID 10001. Импорт приложения не меняет схему.

`docker compose down` останавливает стенд, сохраняя PostgreSQL volume. `docker compose up -d` запускает его снова. Не добавляйте `-v`, если данные нужно сохранить. У Redis отключены RDB и AOF: перезапуск сбрасывает квоты, но не расписание и историю. Образ может создать анонимный volume `/data`, однако приложение не использует его для сохранения счётчиков. Резервное копирование, восстановление и trusted proxy описаны в [deploy/README.md](deploy/README.md).

При недоступном Redis уже запущенный сервер продолжает обслуживать чтение, health и предпросмотр серии. Изменения, включая новый вход, создание демо, профиль и выход, возвращают 503 с `Retry-After: 3`, не меняя PostgreSQL. После восстановления Redis запись работает без перезапуска приложения. Холодный старт требует доступных PostgreSQL, Redis и схемы 0002.

Для запуска без контейнера нужны Python 3.12+, Node.js 24, PostgreSQL 15+ и Redis. Установите `requirements.lock`, соберите клиент (`npm ci`, `npm run build` в `frontend`), задайте `DATABASE_URL`, `REDIS_URL`, `APP_ENV=development`, примените миграции и запустите `python -m uvicorn app.main:app --host 127.0.0.1 --port 8186`. Windows-скрипт `start-local.ps1 -Build` умеет подготовить отдельный локальный PostgreSQL, но требует заранее запущенного Redis и заданного `REDIS_URL`.

Для разработки клиента Vite использует порт 5186 и API на 8186; серверу задайте `PUBLIC_ORIGIN=http://127.0.0.1:5186`.

## Проверки

После подготовки отдельных PostgreSQL `schedule_test` и Redis для тестов:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
cd frontend
npm ci
npm test
npm run build
```

Интеграционные тесты очищают таблицы в `schedule_test`. Используйте только отдельную тестовую БД. Сценарии, команды проверки миграций и границы браузерной проверки описаны в [TESTING.md](docs/TESTING.md).

## Ограничения

Приложение не составляет расписание автоматически, не отправляет уведомления и не импортирует данные из университетских систем. Время отображается по Москве. Черновики тоже резервируют ресурсы; отменённые занятия освобождают время, но остаются в истории. Серия сохраняется целиком либо не сохраняется при конфликте. Перенос и отмена действуют на отдельное занятие.

Демо не заменяет систему учётных записей учебного заведения. Для такого использования потребуются постоянные аккаунты, назначение ролей администратором и отдельные правила хранения данных.
