# Архитектура

Сервер реализован как слоистый монолит. Клиент не принимает окончательных решений о допустимости занятия: проверки повторяются на сервере и закреплены ограничениями PostgreSQL.

```text
React / TypeScript
       │ HTTP + cookie + CSRF
       ▼
FastAPI: маршруты и Pydantic-контракты
       │ права и пространство пользователя
       ▼
Правила расписания и журнал изменений
       │ транзакция SQLAlchemy
       ▼
PostgreSQL: связи, ограничения, интервалы
```

## Основные модули

| Файл | Ответственность |
| --- | --- |
| `app/main.py` | HTTP-маршруты, ответы и обработчики ошибок |
| `app/schemas.py` | Форматы входных данных |
| `app/services.py` | Конфликты, серии, изменения занятий |
| `app/models.py` | Таблицы, связи и ограничения |
| `app/security.py` | Cookie-сессии, CSRF и права |
| `app/workspaces.py` | Ограничение запросов текущим пространством |
| `app/demo.py` | Создание личного демо и примера расписания |
| `app/db.py` | Подключения и границы транзакций |

## Данные и изоляция

Пространство объединяет пользователя, справочники, периоды, расписания, занятия и историю. ORM добавляет область видимости к чтению и проверяет её при записи. Составные внешние ключи не позволяют связать сущности разных пространств.

Студент и преподаватель читают опубликованные занятия. Диспетчер работает с расписанием, администратор дополнительно меняет справочники. В публичной демонстрации роль можно выбирать самостоятельно, но только внутри своего пространства.

Миграция 0001 содержит исходную схему; 0002 добавляет пространства и сохраняет прежние данные в отдельной legacy-области. Парольный режим остаётся в коде для совместимости и тестов, но отключён при `GUEST_MODE=1`.

## Сохранение занятия

Сервер проверяет права, принадлежность справочников, учебный период, время, вместимость и занятость ресурсов. Занятие и запись истории сохраняются одной транзакцией.

Изменяющие запросы в одном пространстве сериализуются advisory lock. PostgreSQL дополнительно запрещает пересечение интервалов группы, преподавателя и аудитории. Это защищает данные и при параллельных запросах. Ожидание блокировки ограничено двумя секундами.

Поле `version` защищает перенос и отмену от сохранения устаревшей формы. Если запись уже изменена, клиент получает 409 и должен загрузить актуальные данные.

## Повторяющиеся занятия

Предпросмотр разворачивает серию в конкретные даты и проверяет их до записи. Сохранение атомарно: конфликт в одной дате откатывает всю серию. Ключ запроса позволяет повторно получить результат сохранённой серии без дублей.

## Сетевые ошибки

Клиент ждёт заголовки и тело ответа не более 15 секунд. По тайм-ауту форма разблокируется, но изменяющий запрос не отправляется автоматически ещё раз: сервер мог уже завершить операцию. Действие «Проверить состояние» заново получает профиль и данные.

Для загрузки расписания и истории предусмотрен ручной повтор. Ошибка загрузки отличается от пустого результата. На стороне БД ограничены ожидание подключения, пула, блокировки и выполнения SQL.

## Границы решения

Сериализация записи внутри пространства упрощает защиту небольшого учебного расписания. При росте нагрузки её нужно оценить измерениями; переход к более мелким блокировкам потребует отдельных конкурентных тестов. Очередь задач и кэш в текущих сценариях не требуются.
