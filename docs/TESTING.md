# Тестирование

Интеграционные проверки используют настоящий PostgreSQL и Redis. Чистые правила и сценарные Protocol-порты отдельно проверяются без БД; архитектурный oracle разбирает AST и имеет запрещённый импорт как отрицательный контроль.

## Автоматические проверки

```powershell
# Используйте отдельные локальные PostgreSQL и Redis.
$env:APP_ENV='test'
$env:DATABASE_URL='postgresql+psycopg://TEST_USER:TEST_PASSWORD@127.0.0.1:TEST_PORT/schedule_test'
$env:REDIS_URL='redis://127.0.0.1:REDIS_TEST_PORT/0'
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m pytest -q

cd frontend
npm ci
npm test
npm run build
```

Backend-тесты очищают таблицы `schedule_test` на том же локальном сервере, который указан в DATABASE_URL. Не запускайте их с подключением к production. Фронтенд-тесты используют встроенный test runner Node.js 24.

Базовые 35 серверных сценариев сохранены; assertions прежних PostgreSQL-счётчиков адаптированы к Redis. Добавлены архитектурные, domain, use-case, Redis, proxy и recovery-тесты. Итоговый текущий счёт показывает pytest; не переносите число из прежнего релиза как доказательство новой проверки. 17 тестов клиента, включая profile readback без повтора PUT, остаются частью обязательной проверки. Возможны два предупреждения устаревающих интерфейсов TestClient/AnyIO.

| Проверяется | Где |
| --- | --- |
| Сессии, CSRF, права, валидация и конфликты | `tests/test_api.py` |

| Автовход, четыре роли, изоляция и сброс демо | `tests/test_guest.py` |

## Проверенный локальный прогон 13.10.2026

Независимый полный прогон после архитектурных изменений: **77 backend + 17 frontend, 0 failures, 0 skips**; TypeScript и Vite build завершились с exit 0, схема — 0002. Доказательства с хэшами исходников и выводов находятся в `08 Аудит/recovery-qa/automated/results.json` относительно корня материалов курсача. Это новый результат, не переоценка исторического браузерного прогона ниже.

Изолированный Compose `mireabackr-recovery` на loopback 8189: реальная остановка Redis сохранила health/GET/preview=200, шесть путей записи вернули 503 с Retry-After:3. Снимки всех 14 таблиц до/после отказа совпали по числу строк и контрольным суммам; запрещённая запись отсутствовала. После запуска Redis запись восстановилась без рестарта app. Отдельные рестарты app и PostgreSQL сохранили сессию, занятие, историю и снимки таблиц. `pg_dump -Fc` восстановлен в новую отдельную БД; все 14 таблиц, schema0002 и контрольная запись совпали со снимком на момент дампа. Рабочие базы и volumes не удалялись. Результат: 7 lifecycle checks PASS; доказательства — `08 Аудит/recovery-qa/compose-lifecycle/results.json`.

Дополнительные 18 измерений (по три на каждый из шести путей) дали 503 за 8,000–8,032 с. DNS при остановленном контейнере занял 8,0803 с; соединение по ранее известному числовому IP — 0,2601 с. Настройки 250 мс ограничивают connect/read, не DNS и не весь HTTP-запрос. Профиль остался прежним без false-success, все измерения профиля уложились в 15-секундный deadline клиента. Значения и helper hash — в `compose-lifecycle/latency-results.json`.

## Новые серверные проверки

| Проверяется | Где |
| --- | --- |
| Dependency rule, отсутствие SQL в API, прежние маршруты/operation names | `tests/test_architecture.py`, `tests/api_contract.json` |
| Московский день, period/capacity/archive, recurrence и прежний hash | `tests/test_domain.py` |
| Лимитер перед UoW, отсутствие mutation при отказе, audit/commit и повторная проверка роли | `tests/test_use_cases.py` |
| Реальный Lua: конкуренция, общие buckets, отсутствие частичного расхода, TTL, NOSCRIPT, ошибка/timeout | `tests/test_redis.py` |
| Точное преобразование смысловых ошибок в прежние HTTP status/detail/Retry-After | `tests/test_error_mapping.py` |
| Trusted proxy, разные IP, игнорирование поддельного XFF | `tests/test_proxy.py` |
| Чтение/preview при отказе Redis, все writes=503, неизменность БД, восстановление и mid-transaction rollback | `tests/test_recovery.py` |

Fixture очищает только `schedule_test`; Redis fixture удаляет свой namespace, Redis-интеграция также вызывает SCRIPT FLUSH. Используйте отдельный Redis процесса проверки. Не запускайте эти тесты параллельно с браузерной сессией на той же БД и не направляйте их на рабочий Redis.

Изолированная проверка runtime-отказа через monkeypatch клиента не заменяет остановку реального контейнера: отдельно выполните `docker compose stop redis`, проверьте health/GET/preview=200 и запись=503 с Retry-After:3, затем `docker compose start redis` и запись=200 без рестарта app. Браузерные и контейнерные результаты фиксируются отдельно; сам факт существования теста не означает его прохождения.

Для чистых проверок: `python -m pytest tests/test_domain.py tests/test_use_cases.py tests/test_proxy.py -q`; Redis/PG не нужны. Полный suite требует схемы 0002 в тестовой БД, в том числе для lifespan-проверки.

## Миграции

```powershell
.\.venv\Scripts\python.exe scripts/verify_migration.py
$env:PYTHONPATH='.'
.\.venv\Scripts\python.exe scripts/verify_guest_migration.py
```

Скрипты рассчитаны на отдельный локальный кластер, созданный `scripts/devdb.py`. При нестандартном порте задайте тот же SCHEDULE_PG_PORT. Проверочные базы создаются отдельно: первая проверка оставляет свою базу для просмотра, проверка гостевой миграции удаляет только созданную ею базу после завершения. Старый seed использует известные локальные тестовые пароли, запрещён в production и не нужен для гостевого входа.

## Сценарный прогон API

При работающем приложении:

```powershell
.\.venv\Scripts\python.exe scripts/smoke_guest.py http://127.0.0.1:8186
```

Прогон создаёт два собственных демо и проверяет роли, изоляцию, справочники, черновик, конфликт, публикацию, перенос, отмену, историю и повторную отправку серии. Сброс выполняется только для созданного им пространства.

## Браузерные сценарии

- Сменить все четыре роли; проверить доступные разделы и повторное открытие страницы.
- Создать период, черновик и занятие; получить конфликт на пересечении ресурсов.
- Проверить серию без частичного сохранения при ошибке.
- Перенести занятие, изменить аудиторию, отменить и открыть историю.
- Проверить пустые фильтры, переходы между неделями, несохранённую форму и клавиатурный фокус.
- Проверить 320 px, 390×844, 820×1180 и 1440×900.

Для воспроизведения сетевых сбоев есть локальная обёртка `scripts/fault_preview.py`. Она доступна только при APP_ENV=development, не должна запускаться на публичном сервере. Режимы задаются в исключённом из Git файле `.local/qa-fault.json`: hang, lost-response, error. После проверки уберите режим.

На текущем архитектурном релизе 13.10.2026 в Microsoft Edge проверены четыре роли, сохранение роли после перезагрузки, черновик, конфликт трёх ресурсов, серия, публикация, перенос, отмена, история и справочники. Страницы расписания, редактора, справочников и профиля просмотрены при 1440×900, 820×1180, 390×844 и 320×844. Горизонтального переполнения на этих экранах не обнаружено. Проверены пустой результат фильтра и возврат клавиатурного фокуса; в финальном чистом проходе сообщений console error/warn не было.

Сетевые сбои отдельно воспроизведены локальной обёрткой на свежем процессе текущего кода. При задержке ответа после сохранения на 20 секунд клиент завершил 15-секундное ожидание и прочитал профиль: новая роль подтвердилась и сохранилась после перезагрузки. При зависшем запросе без записи старая роль осталась текущей, новое значение осталось в форме с предупреждением; кнопка «Проверить состояние» вернула подтверждённые сервером данные. Повторный PUT автоматически не отправляется — это дополнительно проверено клиентскими тестами. Режим внесения сбоев после проверки выключен, процесс остановлен.

После обновления публичного сайта сценарный API-прогон завершился результатом `GUEST_SMOKE_OK`: семь групп проверок охватывают отдельные демо, cookie, роли, изоляцию, справочники, полный цикл занятия, повторную отправку серии и сброс только собственного тестового пространства.

Границы проверки: исходная внешняя сетевая причина пользовательского сбоя не установлена. Проверка намеренно вызванных отказов подтверждает восстановление интерфейса, а не эту причину. Firefox, WebKit, физический Safari и поведение системной мобильной клавиатуры не проверены. Наличие CSS для reduced motion проверено по исходникам, но режим не эмулировался. Полная трасса сетевых запросов и стандартизированное измерение CLS браузерным инструментом не получены; API-сценарии и снимки интерфейса их не заменяют.
